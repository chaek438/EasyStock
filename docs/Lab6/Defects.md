## DEF-01 Повтор складського POST змінює залишок удруге

- Вимога US-RETRY; ризик R1 цілісність даних; сценарії TC-07, TC-08, TC-14, TC-16.
- Знайдено на базовій версії `0eabc81b33955948421838e0a98db920a799a640`. Дата: 01.11.2026.
- Середовище: Linux, Python 3.12.14, SQLite, Flask test client, свіжа демобаза.
- Передумова: вхід адміністратором або комірником; SSD-480 має залишок 17.
- Кроки: надіслати POST /api/stock/receipt з product_id=1, quantity=20 і Idempotency-Key=lab6-lost-response; повторити той самий JSON та ключ. Для другого прояву повторити списання -3 на свіжій базі.
- Очікування: надходження має один ефект, залишок 37; списання має один ефект, залишок 14. Повертається початковий результат, аудит не дублюється.
- Факт до виправлення: надходження 57, списання 11. Обидва запити повертають 201; два регресійні приклади Fail.
- Повторюваність: 2 з 2 автоматизованих прикладів на ізольованих даних.
- Severity **Major**: помилка спотворює важливий складський облік при повторі після втрати відповіді. Primary потік доступний; втрату всієї бази чи обхід авторизації не виявлено.
- Priority **High**: сценарій можливий під час звичайного повтору дії і має бути виправлений до навчального релізу.
- Першопричина: сервер не зберігав ідентифікатор наміру; кожний POST виконував нову транзакцію. Блокування кнопки саме по собі не захищає від повтору після невідомого результату.
- Виправлення: унікальна пара автор/ключ, SHA-256 канонічного JSON і тип операції, збережена відповідь у stock_requests; цей запис, склад і аудит фіксуються однією транзакцією. Конфлікт ключа з іншим наміром дає 409. UI повторно використовує ключ для незмінених даних після помилки транспорту.
- Retest: 23 нові API-приклади Pass; початкові два тепер дають 37 і 14. Regression: 63 API-тести, 18 HTTP/React DOM і 8 релізних перевірок Pass.
- Статус: **Closed** після власного retest. Самоперевірка не є незалежним review.
- Локальна гілка: fix/lab6-stock-retry. Відтворення: коміт ce14d0a з двома падаючими тестами. Виправлення DEF-01: `459101d8c30f39d31de31719354d149afe2cdf4b`. Поточний перевірений код: `6d7f8d951a23f205477960efdc3ec79648f6bb78`.
- Докази: [до зміни](evidence/defect-before.txt), [retest](evidence/retest.txt), [регресія](evidence/regression-api.txt), [втрата відповіді у React DOM](evidence/smoke-ui.json), [рестарт](evidence/release-smoke.json).

## Життєвий цикл

New → Triaged → In progress → Ready for retest → Verified → Closed. Усі переходи належать одному автору й підтверджені локальними тестами та commits; окремого схвалення іншою людиною немає. Зміни оформлено в [PR №3](https://github.com/chaek438/EasyStock/pull/3). Окремий GitHub issue не створювався; цей файл є журналом дефекту.

## Залишкові обмеження

Запит без Idempotency-Key зберігає попередній контракт і є новою операцією. Ключ у React зберігається лише до закриття/перезавантаження компонента. За невідомого результату після перезавантаження вкладки спочатку перевіряють історію; не створюють новий ключ навмання. Це описані межі протоколу, а не підтвердження всіх можливих мережевих сценаріїв.
