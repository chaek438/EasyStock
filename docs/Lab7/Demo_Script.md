# Демонстрація EasyStock за сім хвилин

Виконав: Бондаренко Сергій

Реліз: [v1.0.0](https://github.com/chaek438/EasyStock/releases/tag/v1.0.0). Дата підготовки: 04.11.2026. Усі ролі доповідача та оператора поєднує один виконавець. Контрольний технічний прогін автоматизовано, повний усний прогін та захист виконує автор перед здачею.

## Початкові дані та запуск

Встановити Python 3.11+, розпакувати проєкт та виконати інструкцію README. Готовий frontend вже є у frontend/dist. Перший запуск потребує інтернету для Python-залежностей. Для автономного показу встановити їх заздалегідь.

Для нового показу зупинити наявний сервер і вибрати нову окрему демобазу. Не видаляти робочу базу. Якщо файл нижче існує, використати інше нове ім’я. У PowerShell із кореня EasyStock після встановлення залежностей:

```powershell
$demoDb = (Join-Path (Get-Location) "database\lab7-demo-NEW.db").Replace("\", "/")
$env:DATABASE_URL = "sqlite:///$demoDb"
.\.venv\Scripts\python.exe start.py --demo --port 5000
```

Linux або macOS:

```bash
DATABASE_URL="sqlite:///$PWD/database/lab7-demo-NEW.db" .venv/bin/python start.py --demo --port 5000
```

Відкрити http://127.0.0.1:5000. Демокористувач keeper@easystock.local, пароль DemoStock2026!, лише для локальної навчальної бази. Для завершення показу менеджер: manager@easystock.local з тим самим демонстраційним паролем. Реальних персональних даних у сценарії немає. Початковий товар SSD-480 має 17 одиниць. Повторний запуск --demo з існуючою базою не скидає операції.

## Підготовлені кроки

### D0 0:00–0:30 Визначити реліз і стартовий стан

- Мета: Визначити реліз і стартовий стан.
- Початковий стан: Сервер з окремою свіжою демобазою, форма входу, v1.0.0.
- Дія: Показати версію, health та увійти як keeper@easystock.local.
- Очікування: Комірник бачить головну сторінку. Використано вигадані демодані.
- Доказ: US-01; TC-01; technical-rehearsal.json, перевірки 1 і 5.
- Резерв: 01-login.png, 03-dashboard.png у docs/screenshots або docs/Lab7/evidence.

### D1 0:30–1:00 Пояснити користувацьку цінність

- Мета: Пояснити користувацьку цінність.
- Початковий стан: Відкрита головна сторінка.
- Дія: Пояснити, що комірник має знайти товар, провести надходження і списання та побачити автора операції.
- Очікування: Названо завершений результат і межі локального MVP.
- Доказ: Розділи 1–2 звіту; слайди 2–3.
- Резерв: 03-dashboard.png у docs/screenshots або docs/Lab7/evidence.

### D2 1:00–1:40 Знайти товар у відомому стані

- Мета: Знайти товар у відомому стані.
- Початковий стан: Комірник увійшов. Демобаза ще не змінювалася.
- Дія: У розділі «Товари» знайти SKU SSD-480 і відкрити картку.
- Очікування: Знайдено один товар. Початковий залишок 17. Якщо число інше, до показу підготувати іншу свіжу демобазу.

### D3 1:40–3:10 Провести надходження і перевірити аудит

- Початковий стан: Картка SSD-480, залишок 17.
- Дія: Відкрити «Надходження», ввести 20, підтвердити один раз. Перейти до історії.
- Очікування: Залишок 37. Є документ надходження й один новий рух із кількістю 20, автором і часом.

### D4 3:10–4:30 Довести захист від надмірного списання

- Мета: Довести захист від надмірного списання.
- Початковий стан: Залишок 37, відома кількість рухів історії.
- Дія: У формі списання ввести 40 і коментар та підтвердити. Показати повідомлення і збережені поля.
- Очікування: API повертає 409 із доступною кількістю. Залишок 37 та історія незмінні, форма не втрачає введені дані.

### D5 4:30–5:20 Завершити коректну операцію

- Мета: Завершити коректну операцію.
- Початковий стан: Форма після відмови, залишок 37.
- Дія: Замінити кількість на 3, підтвердити і відкрити історію.

### D6 5:20–6:10 Показати доказ виправлення повторного запису

- Мета: Показати доказ виправлення повторного запису.
- Початковий стан: Підготовлений термінал або файл demo-test.txt. Тести використовують власні окремі бази.
- Дія: Показати TC-07 і TC-08 та виконати команду pytest з Demo_Script.md або відкрити збережений результат.
- Очікування: 2 passed. TC-07: 17 +20 двічі з тим самим ключем дає 37. TC-08: 17 −3 двічі дає 14. Це окремі тести, тому 14 не є залишком поточного UI-демо.
- Доказ: US-10; DEF-01; tests/test_release.py::test_replayed_stock_request_has_one_effect.
- Резерв: evidence/demo-test.txt, docs/Lab6/evidence/retest.txt у docs/screenshots або docs/Lab7/evidence.

### D7 6:10–7:00 Пояснити доступ і завершити показ

- Мета: Пояснити доступ і завершити показ.
- Початковий стан: Комірник увійшов, показаний залишок 34.
- Дія: Вийти, увійти як менеджер і показати режим читання. Завершити поясненням обмежень та наступного кроку.
- Очікування: Після виходу захищений запит дає 401. Менеджер читає каталог, прямий запис дає 403. Названо потребу перевірки у двох реальних браузерах.
- Доказ: US-14, NFR-03; TC-01, TC-10; technical-rehearsal.json, перевірки 15–17.
- Резерв: 11-users.png та журнали автоматизованих перевірок у docs/screenshots або docs/Lab7/evidence.

## Команда для показу тесту

Із кореня EasyStock, в окремому терміналі:

```powershell
.venv\Scripts\python.exe -m pytest tests/test_release.py -k replayed_stock_request -q
```

У Linux/macOS замінити виконуваний файл на .venv/bin/python. Очікується 2 passed, 21 deselected. Перед показом встановити залежності з backend/requirements.txt. Два тести створюють власні ізольовані бази та не змінюють базу UI-демонстрації. Якщо часу мало, відкрити збережений фактичний результат evidence/demo-test.txt.
