# EasyStock 1.1.0 Складське ядро

Виконав: Бондаренко Сергій. Група: 3ІПЗс-24.

Етап 1 з [плану розширення](../ROADMAP.md) додає облік запасів за складами. Каталог спільний, але кількість, перегляд рухів, надходження, списання, звіти й показники залежать від активного складу. У вкладці **Склади** видно всі локації та зведення по кожній. Назву й адресу можна змінити; код складу зберігається для однозначного посилання.

## Запуск

1. Розпакуйте ZIP в окрему папку. Якщо працює попередня версія EasyStock, зупиніть її, щоб звільнити порт 5000.
2. У Windows відкрийте `run_demo.bat`; у Linux/macOS — `bash run_demo.sh`. Потрібен Python 3.11 або новіший, на першому встановленні бібліотек — інтернет. Зібраний інтерфейс уже входить у комплект.
3. У браузері відкрийте [127.0.0.1:5000](http://127.0.0.1:5000) і скористайтеся кнопками демонстраційних ролей. Для сценарію нижче потрібні Основний і Резервний склади; обидва є у свіжій демобазі.

## Як оновити базу без втрати історії

Після коректної зупинки старої версії скопіюйте або відновіть стару базу до нової папки. На першому запуску EasyStock 1.1.0 створить поруч файл `easystock-before-phase1-*.db`, перенесе наявні залишки та рухи на **Основний склад** і залишить товари, користувачів, надходження й ідентифікатори записів. Це одна транзакція: у разі помилки зміни схеми й даних відкотяться. Старі рухи залишаються в історії; нумерація документів `СК-…` застосовується до нових операцій.

Демо заповнюється лише за відсутності користувачів. Після оновлення заповненої бази створіть додатковий склад у довіднику під адміністратором. Щоб повернутися до версії 1.0.0, використовуйте передміграційну копію разом із попереднім кодом; вона не містить операцій, зроблених пізніше в 1.1.0.

## Сценарій демонстрації

У свіжій демобазі товар **SSD-480** має 17 одиниць на Основному складі і 0 на Резервному.

| Крок | Очікуваний результат |
| --- | --- |
| Комірник створює переміщення 5 SSD-480 з Основного складу на Резервний. Зберігає чернетку й передає на погодження. | Залишки досі **17 / 0**. Документ має номер та автора. |
| Адміністратор відкриває документ, перевіряє позиції й проводить його. | Залишки **12 / 5**. Є два пов’язані рухи −5 і +5. Повторне проведення не змінює залишки. |
| На Резервному складі комірник фіксує фактичні 4 одиниці. Адміністратор проводить інвентаризацію. | За обліком 5, фактично 4, різниця −1. Підсумок **12 / 4**. Якщо товар змінився після завантаження форми або після збереження чернетки, потрібно повторити підрахунок. |
| Адміністратор створює сторно інвентаризації, вказавши причину. | Окремий документ додає 1. Залишки **12 / 5**, вихідний документ і рухи залишаються видимими. |
| Відкрийте «Друк / PDF» або експортуйте залишки і журнал для обраного складу. | Друк містить реквізити, позиції та проведені рухи. CSV відповідає обраному складу. |
| Увійдіть як менеджер. | Можна переглянути документи й залишки. Погодження, зміна складів, імпорт і резервне копіювання недоступні. |

Переміщення на етапі 1 змінює обидва склади в один момент. Рух у дорозі та окреме підтвердження приймання належать до етапу 2. Швидкі форми «Надходження» та «Списання» зберігають попередні права і створюють вже проведені документи. Усі чернетки з розділу «Документи» проходять погодження. Сторно може бути відхилене, якщо зворотне списання створить нестачу.

## Імпорт та експорт

Завантажте шаблон у розділі **Імпорт і резервні копії**. Збережіть файл як CSV UTF-8, залиште назви стовпців і вкажіть наявну категорію. Підтримуються розділювачі `;` та `,`, до 500 позицій і 450 КБ у формі. Перед імпортом форма показує кількість коректних рядків, приклади й помилки. При помилці в будь-якому рядку не додається жоден товар. Нові товари мають нульові залишки; їхнє перше надходження оформлюється складським документом. Наявні SKU не перезаписуються.

Експорт каталогу охоплює всі активні товари. Експорт залишків працює для активного складу, а експорт зі сторінки історії враховує також її поточні фільтри. CSV можна відкрити в Excel, обравши UTF-8 та розділювач `;` за потреби.

## Резервна копія і відновлення

Адміністратор завантажує `.db` у розділі **Імпорт і резервні копії**. Копія враховує підтверджені записи з журналу SQLite, проходить перевірку цілісності й містить дані про запаси, документи та користувачів без активних сеансів. Зберігайте файл приватно.

Для перевірки відновіть копію в **новий** файл. У Windows PowerShell із кореня проєкту:

```powershell
.\.venv\Scripts\python.exe scripts\db_admin.py restore "D:\Backups\easystock-backup.db" database\easystock-restored.db
$env:DATABASE_URL = "sqlite:///" + ((Resolve-Path database\easystock-restored.db).Path -replace '\\','/')
.\.venv\Scripts\python.exe start.py --port 5001
```

Відкрийте [127.0.0.1:5001](http://127.0.0.1:5001), увійдіть знову та перегляньте залишки і документи. Поточна база не перезаписується. Для локального резервування з командного рядка використайте `scripts/db_admin.py backup ВХІДНА_БАЗА НОВА_КОПІЯ`.

## Перевірки для розробника

```bash
.venv/bin/python -m pytest -q
.venv/bin/python scripts/smoke_mvp.py --with-ui --json /tmp/easystock-phase1-smoke.json
```

Для `--with-ui` потрібні Node.js і встановлені залежності з `frontend/package-lock.json`. Серверні тести перевіряють міграцію v1.0.0, переказ залишків в одній транзакції, одночасне проведення, простежуваність, застарілу інвентаризацію, імпорт і відновлення. React DOM проходить через справжній HTTP API з тимчасовою базою. Ця перевірка не вимірює зовнішній вигляд у реальному браузері.
