## API-докази

- Успішний / неправильний login; паролі — хеші; expiry; logout відкликає сеанс, повторне використання старого cookie не працює.
- Неавторизований API недоступний, запис без CSRF відхилено, ролі контролюються сервером.
- SSD-480: 17 + 20 = 37; запит списати 40 → 409, залишок і кількість записів не змінюються; списати 3 → 34.
- Дві одночасні спроби списати по 15 при залишку 17: одна → 201, інша → 409, кінцевий залишок 2.
- Штучна помилка запису аудиту після SQL-оновлення залишку: stock, Receipt, ReceiptItem та Movement відкатуються разом.
- Надходження з кількома товарами; дубль позиції / невідомий товар відхиляє весь документ.
- 0, від’ємна, дробова, boolean, null, текстова й надмірна кількість відхиляються без зміни даних.
- Неприпустима ціна, дубль SKU, Unicode-пошук, буквальні `%`, фільтри, пагінація, low-stock.
- CRUD довідників і товарів, архівація, збереження історії, заборона архівації з ненульовим stock.
- Блокування користувача відкликає доступ; адміністратор не може заблокувати себе.
- SQL CHECK quantity>=0, FK, відсутні API-маршрути повертають 404.

## React DOM із реальним API

Запускався повний React-застосунок із HTTP-запитами до Waitress та окремою демобазою:

1. Вхід адміністратора та dashboard.
2. Пошук «КЛАВІАТУРА», порожній результат, очищення фільтрів.
3. Створення нового товару через модальну форму, початковий залишок 0.
4. Надходження 17, потім +20: залишок 37.
5. Списання 40 відхилене; поле кількості=40, коментар і залишок=37 збережені.
6. Списання 37: новий залишок 0.
7. Історія містить товар і автора; архівація зберігає історію.
8. Вихід, вхід менеджера; немає пунктів надходжень/користувачів, прямий перехід на форму показує обмеження доступу.

Виправлення за результатами перевірки: збереження вже завантаженого вмісту під час фонового оновлення, щоб success-форма залишалася видимою та доступною.

Це перевіряє компоненти, введення, події та API-контракт; **не перевіряє CSS-розкладку, мобільний viewport чи сумісність із двома браузерами**. NFR-04 залишається непідтвердженою до локального E2E.

## Відтворення

```bash
# Із кореня EasyStock
.venv/bin/python -m pytest -q
.venv/bin/python -m pytest tests/test_api.py::test_500_product_p95 -q -s
# В окремому терміналі
.venv/bin/python start.py --demo
# Frontend
cd frontend
npm ci
npm run build
npm run test:ui
npx playwright install chromium firefox
npm run test:e2e
```

Для тестів UI використовуйте окрему базу. Браузерний сценарій створює власні товари, перевіряє persistence після reload, ролі та viewport 390×844, створює скриншоти в docs/screenshots. У цьому архіві немає скриншотів, що не були фактично отримані.

Час API виміряний локально через Flask test client, не через мережу чи production load. Затримка реальної мережі й інші комп’ютери можуть дати інший результат. Час пошуку людиною <=30с вимірюється у walkthrough окремо.
