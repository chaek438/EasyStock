# ADR 003 Залишки та складські документи

**Статус:** прийнято для EasyStock 1.1.0.

**Контекст.** У v1.0.0 один товар мав один глобальний залишок. Кілька складів потребують незалежної кількості для кожної локації. Важливо зберегти дані та не допустити половинного переміщення, повторного проведення або перезапису свіжого залишку застарілим підрахунком.

**Рішення.** Таблиця `warehouses` зберігає склади, `stock` має унікальну пару `(product_id, warehouse_id)`. Відсутній рядок означає нульовий залишок. `stock_documents` і `stock_document_lines` зберігають номер, автора, стан та позиції. Проведення додає записи до `stock_movements` і змінює залишки однією транзакцією. У переміщенні сума двох змін для товару дорівнює нулю. Сторно є новим документом зі зворотними змінами та унікальним посиланням на первинний документ.

**Захист від суперечливих змін.** Запис бере блокування SQLite перед прийняттям рішення щодо актуального стану. Кількість оновлюється в межах допустимого діапазону, а ревізія залишку зростає при кожній зміні. Інвентаризація зберігає облікову кількість і ревізію; документ відхиляється, якщо ревізія змінилася, навіть коли числовий залишок згодом повернувся до попереднього значення.

**Альтернативи.** Окрема база на кожен склад ускладнила б атомарне переміщення і зведення. Зберігання тільки журналу спростило б модель запису, але вимагало б підсумовувати всю історію для частих читань. Окрема колонка кількості на кожен склад вимагала б зміни схеми для додавання локації.

**Наслідки.** Покажчики за складом підтримують журнал і зведення. Міграція додає Основний склад, розміщує там попередні рухи й залишки та створює передміграційну копію. SQLite збережено для простого запуску; перенесення на PostgreSQL і перевірка паралельності повних замовлень залишаються завданнями наступних етапів.
