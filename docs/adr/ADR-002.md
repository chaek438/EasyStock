# ADR-002: транзакції та обмін даними

Статус: Accepted.

Контекст: залишок і журнал рухів мають бути узгодженими, зокрема при одночасних запитах.

Рішення: SQLite як primary store, JSON/HTTP API, бізнес-правила у Stock Service. SQL constraints (CHECK, UNIQUE, FK), foreign_keys=ON, WAL, busy_timeout. Надходження виконує атомарний SQL increment, списання — conditional decrement `WHERE quantity >= requested`. Документ, позиції та рухи зберігаються одним commit; помилки відкатують транзакцію.

Альтернативи: читання залишку та Python-перезапис без умовного SQL, JSON-файл, MongoDB, PostgreSQL одразу. Неумовний перезапис створює ризик втрачених оновлень; файл не забезпечує необхідних constraints.

Наслідки: неможливий від’ємний залишок; друге паралельне надмірне списання відхиляється. SQLite серіалізує запис; для високого навантаження потрібна інша БД. Історію не редагують і не видаляють через API; товари архівують тільки після списання залишку.

Авторизація: випадкові серверні токени, у БД SHA-256 хеш токена, HttpOnly/SameSite cookie, окремий CSRF, 8 годин TTL, роль завантажується з БД при кожному запиті, logout та блокування відкликають сеанси. Паролі — Werkzeug scrypt.
